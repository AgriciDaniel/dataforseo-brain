# Review: Backlinks + Domain Analytics + Content Analysis

Scope: `cap-backlinks-api`, `cap-backlinks-bulk-metrics`, `cap-domain-analytics`, `cap-content-analysis-api`; raw `backlinks/`, `domain-analytics/`, `content-analysis/`. Spot-checked vs live docs at https://docs.dataforseo.com/v3/ on 2026-06-26.

## What checks out (verified against live docs)
- **Backlinks add-on / 40204 (the flagged concern): ACCURATE.** Live errors page (https://docs.dataforseo.com/v3/appendix/errors/) gives 40204 = "Access denied. Visit Plans and Subscriptions to activate your subscription and get access to this API." The cost log shows `summary`, `referring_domains`, `anchors`, `bulk_ranks`, `bulk_spam_score` all returned `task_status_code: 40204, cost 0.0`. The wiki's "paid add-on / subscription required" framing is correct.
- **Bulk target limits: ACCURATE.** 1,000 targets/call, and `bulk_pages_summary` additionally caps at 100 distinct domains — confirmed on https://docs.dataforseo.com/v3/backlinks/bulk_pages_summary/live/.
- **Spam score / rank facts: ACCURATE.** `spam_score`/`backlinks_spam_score` 0–100; `rank` 0–100 or 0–1000 via `rank_scale` (default `one_thousand`). Matches summary/bulk_spam_score/backlinks live docs.
- **New/lost window (≤365 days, default 30), summary defaults, history start 2019-01-01, domains_by_technology limit ≤10,000 + offset_token >100,000, content-analysis trend start 2022-10-31, whois cost $0.101, domain_technologies cost $0.01: ALL ACCURATE** vs live docs and the cost log.
- **domain_technologies "one task at a time": ACCURATE** — live doc literally states "You can set only one task at a time."

## Findings

| Severity | Location | Issue | Recommended fix |
|---|---|---|---|
| MEDIUM | cap-content-analysis-api (Gotchas, line ~57) | Claims `id_list` "only surfaces tasks from the past month." Live doc (https://docs.dataforseo.com/v3/content_analysis/id_list/) and raw `content-analysis-id_list.md`: task IDs are retrievable up to **6 months** back (`datetime_from` max = 6 months); the **1-month** limit applies only when `include_metadata: true`. | Reword to: "id_list returns task IDs from up to 6 months back (10 calls/min); metadata is only available for tasks created in the past month, which also caps the lookback to 1 month when `include_metadata` is set." |
| MEDIUM | cap-backlinks-api ("What it covers" + Gotchas) | Omits the free `GET /v3/backlinks/index` endpoint and the index-size facts that the raw `backlinks-reference.md` captured (800.6B backlinks / 80.8B pages / 770.7M domains; monthly history from 2021-10-01). Live https://docs.dataforseo.com/v3/backlinks/index/ confirms it is free ("Your account will not be charged"). This is the headline Ahrefs/Majestic comparison stat and the only Backlinks call that may run without the paid add-on. | Add `/v3/backlinks/index` (free GET) to coverage with the index-size numbers; note it lets you verify index scale before buying the add-on (and flag that whether it is itself gated by the add-on was not empirically tested). Optionally add the `/v3/backlinks/filters/` reference too. |
| LOW | cap-content-analysis-api (line ~30, "Free helpers") | Lists the filter helper as `/v3/content_analysis/filters/`, but the actual API call path is `GET /v3/content_analysis/available_filters` (raw `content-analysis-available_filters.md` Path line). `/filters/` is only the docs-page slug; copying it as the API path 404s. (Backlinks really is `/filters/`, domain_analytics is `/technologies/filters/` — content_analysis is the odd one.) | Change to `/v3/content_analysis/available_filters`. |
| LOW | cap-backlinks-api (Overview, line ~22) | "every live call returned status 40204" is imprecise: the HTTP `status_code` was 20000; only the per-task `task_status_code` was 40204 (line ~52 states this correctly). | Align line 22 to "every live call returned task status 40204". |
| LOW | cap-backlinks-api (Overview/Gotchas, history) | Says history runs "from January 2019" but omits that `new_backlinks`/`lost_backlinks`/new-lost referring-domain fields only populate from **May 2021** onward (raw `backlinks-history.md`, live history doc). | Add the May-2021 caveat for new/lost fields so users don't expect velocity data back to 2019. |
| LOW | cap-content-analysis-api (Key parameters table) | Merged param table lists `positive_connotation_threshold`/`sentiments_connotation_threshold` and `date_from`/`date_to`/`date_group` without attribution. Per raw docs the thresholds exist on summary/sentiment_analysis/rating_distribution but **not** on `search`; the date params exist only on phrase_trends/category_trends. Could mislead someone building a `search` call. | Annotate each row with the endpoint(s) it applies to (as the bulk-metrics note already does for `rank_scale`). |
| LOW | cap-backlinks-api (Key parameters table) | Conflates the `summary` filter param `backlinks_filters` with the backlinks-list `filters`/`order_by`/`limit`/`offset` (summary has none of the latter and uses `backlinks_filters`, not `filters`). | Split the row: note `backlinks_filters` for summary; `filters`/`order_by`/`limit`/`offset` for backlinks/anchors/referring_domains/etc. |

## Verdict
Scope is solid and largely accurate — the flagged 40204 add-on claim and all index-size/spam-score/rank/bulk-target facts verify clean against live docs. Two worth fixing: a real factual error in the content-analysis `id_list` lookback (1mo vs 6mo) and the missing free `/v3/backlinks/index` endpoint + 800B-index stat (a competitive selling point). The rest are LOW precision/attribution tidy-ups.
