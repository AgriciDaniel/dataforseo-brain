# Review: DataForSEO Labs + OnPage (cap-labs-keyword-research, cap-labs-competitor-research, cap-labs-market-analysis, cap-onpage-api)

Reviewer pass date: 2026-06-26. Method: read the four wiki notes + matching raw docs under `.raw/sources/dataforseo-research/{labs,onpage}/`, then spot-checked the live docs at https://docs.dataforseo.com/v3/ (Labs overview, OnPage overview, apple/keywords_for_app, instant_pages, task_post).

## Endpoint-coverage check (the headline concern)

- **Labs:** Every endpoint on the live Labs overview is represented in the wiki. Google keyword-research (8), market-analysis (5), competitor-research (12); Amazon (all 6: `bulk_search_volume`, `related_keywords`, `ranked_keywords`, `product_rank_overview`, `product_competitors`, `product_keyword_intersections`); Apple App Store (all 4: `app_competitors`, `app_intersection`, `bulk_app_metrics`, `keywords_for_app`); Google Play (all 4: `app_competitors`, `app_intersection`, `bulk_app_metrics`, `keywords_for_app`). **No missing Labs endpoints found.**
- **OnPage:** All live OnPage endpoints are present, including the three the task flagged: `lighthouse`, `microdata`, `instant_pages`. Also `page_screenshot`, `content_parsing`, `pages_by_resource`, `waterfall`, `keyword_density`, `raw_html`, `duplicate_content`, `redirect_chains`, `non_indexable`, `force_stop`. **No missing OnPage endpoints found.**
- **Limits spot-checked against raw + live and confirmed accurate:** keyword_overview max 700 keywords; keyword_ideas max 200; bulk_keyword_difficulty / search_intent max 1000; keywords_for_categories max 20 category_codes; OnPage task_post max 100 tasks/POST; instant_pages max 20 tasks/request and no more than 5 identical domains; raw_html 7-day retention vs 30-day for other retrieval endpoints; duplicate_content SimHash 0-10 default threshold 6; apple/keywords_for_app still **US location / English only** (live doc still says "currently supports the US location only" and "the English language only").

## Findings

| Severity | Location | Issue | Recommended fix |
|---|---|---|---|
| MEDIUM | cap-onpage-api (line 30, 46) | The Lighthouse sub-API list shows only `task_post`, `tasks_ready`, `task_get/json/$id`, `live/json`. It omits the three documented helper/metadata endpoints `GET /v3/on_page/lighthouse/languages`, `/v3/on_page/lighthouse/audits`, `/v3/on_page/lighthouse/versions` (present in raw `onpage-lighthouse.md` and on the live overview). Line 46 also lists Lighthouse categories as "performance, accessibility, best_practices, seo" but omits the **PWA** category that the raw and live docs include. | Add the three helper endpoints to the Lighthouse bullet and add `pwa` to the categories list (cite https://docs.dataforseo.com/v3/on_page/lighthouse/overview/). |
| LOW | cap-labs-competitor-research (line 50) | The cost-log paragraph lists `historical_keyword_data` (a keyword-research endpoint that belongs to cap-labs-keyword-research) inside the competitor-research note. The competitor historical endpoints are `historical_rank_overview`, `historical_serps`, and `historical_bulk_traffic_estimation`. | Replace `historical_keyword_data` with the correct competitor historical endpoint(s) or drop it to avoid mis-routing. |
| LOW | cap-labs-keyword-research (line 62) / cap-labs-competitor-research (line 60) | "amazon bulk_search_volume covers a broader marketplace set" is vague. Raw `amazon-bulk-search-volume.md` enumerates 16 marketplaces (US, UK, CA, AU, DE, FR, IT, ES, NL, AT, IN, MX, SG, EG, SA, UAE), vs the US/EG/SA/UAE-only restriction on the other Amazon Labs endpoints. | Name the 16 supported marketplaces (or link the raw) so operators do not assume bulk_search_volume is restricted to the 4-market set. |
| LOW | cap-onpage-api (line 30) | Lighthouse `task_get` path is written as `task_get/json/$id`; the live docs also expose `task_get/html/$id`. Minor, but the note implies JSON-only retrieval. | Note that `task_get` supports both `/json/` and `/html/` result formats. |
| INFO | cap-onpage-api (line 46) | `page_timing` is described with `first_input_delay`; FID was retired from Core Web Vitals (replaced by INP, Mar 2024). This is **not an error** — DataForSEO's OnPage schema still returns its own synthetic `first_input_delay` field, so the note is faithful to the API. | No change needed; optionally add a one-line note that DataForSEO reports lab FID, not field INP. |

## Verdict

Solid. Endpoint coverage is complete for both Labs (all Amazon / Apple App Store / Google Play variants) and OnPage (lighthouse, microdata, instant_pages, page_screenshot all present), and the quantitative limits I spot-checked against the live docs are accurate. Only one MEDIUM (missing Lighthouse helper endpoints + PWA category) and a few LOW polish items; nothing blocking and nothing materially outdated.
