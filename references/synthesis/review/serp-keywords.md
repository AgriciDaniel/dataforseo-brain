# Review: SERP + Keywords Data scope

Scope audited: `cap-serp-api`, `cap-serp-google-verticals`, `cap-serp-non-google-engines`, `cap-keywords-data-api`, `cap-trends-and-clickstream`; platforms `plat-google-search`, `plat-bing-search`, `plat-youtube`, `plat-other-search-engines`. Raw: `serp/`, `keywords-data/`. Spot-checked against live docs at https://docs.dataforseo.com/v3/ on 2026-06-26.

Method: read each wiki note + matching raw doc, then fetched the live SERP overview, Keywords Data overview, and individual endpoint pages (AI Mode, AI Summary, Screenshot, Bing search_volume, YouTube comments, Google Maps) to confirm endpoints, params, tiers, and costs.

## Findings

| Severity | Location | Issue | Recommended fix |
|---|---|---|---|
| HIGH | cap-serp-api / cap-serp-google-verticals / cap-geo (all SERP notes) | The **AI Summary** endpoint `POST /v3/serp/ai_summary` is entirely absent from the brain. It generates an AI-written summary of an existing SERP using a `task_id` from a prior SERP POST, with `prompt` (custom instruction, max 2000 chars), `support_extra` (default true), `fetch_content` (default false), `include_links` (default false). Cost **$0.01/request**; task_id valid 30 days. For a brain that markets AI-search/GEO coverage (AI Mode, AI Overview tracking), omitting a shipped AI-summarization endpoint is a real capability gap. | Add to `cap-serp-api` "What it covers" as a root-level (engine-agnostic) SERP utility, and cross-link from `cap-geo-ai-search-optimization` / `play-ai-visibility-tracking`. Cite https://docs.dataforseo.com/v3/serp/ai_summary/ |
| MEDIUM | cap-serp-api / .raw/sources/dataforseo-research/serp/_module-index.json | The **Screenshot** endpoint `POST /v3/serp/screenshot` is missing from the wiki and raw module index. Renders a screenshot from a prior SERP HTML task; requires `task_id` (usable within 7 days of creation), supports browser resolution/scale/page-number params; image kept 1 day. Cost **$0.004/request**. | Add a one-line mention of the Screenshot utility endpoint to `cap-serp-api` and to the serp raw module index. Cite https://docs.dataforseo.com/v3/serp/screenshot/ |
| MEDIUM | cap-serp-api (line 25) / cap-serp-google-verticals / serp raw module index | Google **Dataset Info** endpoint `/v3/serp/google/dataset_info/` is missing. The wiki covers `dataset_search` but not its sibling `dataset_info`, which the live SERP overview lists as a distinct endpoint. | Add `dataset_info` alongside `dataset_search` in `cap-serp-google-verticals` and the raw module index. Cite https://docs.dataforseo.com/v3/serp/overview/ |
| MEDIUM | cap-serp-api (line 25) | Inaccurate count: "Google organic and **50+ verticals**". Google exposes ~15-17 vertical endpoints (organic, ai_mode, maps, local_finder, news, events, images, search_by_image, jobs, autocomplete, dataset_search, dataset_info, finance x4, ads_search, ads_advertisers), not 50+. The "50+" correctly describes SERP feature *element types* returned within the organic endpoint (as `plat-google-search` line 24 uses it correctly: "50+ feature element types"). The hub conflates the two and overstates vertical count ~3x. | Reword to "Google organic (with 50+ SERP element types) and ~15 verticals". |
| LOW | cap-serp-google-verticals (line 18 lead sentence) | The note's one-line summary lists "AI Mode, AI Overview, Maps, Local Finder, News, Events, Images, Jobs, Autocomplete, Ads, and Finance" but omits **Search By Image** and **Dataset Search** even though both are covered in the body (and Dataset Info is missing entirely, per the MEDIUM above). | Add Search By Image + Dataset Search/Info to the lead sentence for completeness. |
| LOW | cap-trends-and-clickstream (params table) | The Google Trends `category_code` parameter (search category filter, default 0 = all categories) is present in raw `google-trends.md` but absent from the wiki params table. It is a real query lever for category-scoped trend data. | Add `category_code` to the Google Trends parameters in `cap-trends-and-clickstream`. |
| LOW | cap-keywords-data-api / plat-bing-search (Bing keyword_performance) | The wiki cites a 1,000-keyword cap for Bing `keyword_performance`; the live doc is internally inconsistent and also states "up to 2500 keywords in one keywords array" (noted in raw `bing-ads.md`). Not a wiki error, but the discrepancy is uncaptured. | Add a footnote that DataForSEO docs quote both 1,000 and 2,500 for this endpoint; treat 1,000 as the safe limit. |

## Verified accurate (no change needed)
- 7 supported engines (Google, Bing, YouTube, Baidu, Yahoo, Seznam, Naver) — complete; no missing engines in the live overview.
- Google AI Mode: Advanced + HTML only, no Regular tier; element types `ai_overview` / `ai_overview_reference` / `ai_overview_shopping` — matches live doc.
- Bing keyword endpoints limited to English/French/German (en/fr/de) — confirmed on live `search_volume`.
- YouTube `video_info` / `video_comments` / `video_subtitles` are desktop-only — confirmed on live `video_comments`.
- Google Maps: default depth 100, max 700, billed per SERP of up to 100, mobile capped at 20 — confirmed on live doc.
- Clickstream (3 endpoints, Live-only), DataForSEO Trends (4 endpoints, Live-only), Google Trends throttles (250 live tasks/min, 500K/day) — all match live + raw.
- Google Ads 12 req/min/account limit, per-request flat pricing, `impressions`/`ctr` deprecated in ad_traffic_by_keywords — accurate.

Verdict: Scope is largely solid and accurate; the one material gap is the missing AI-search endpoints (AI Summary + Screenshot) plus a count-overstatement ("50+ verticals"). One HIGH, three MEDIUM, three LOW; no BLOCKERs.
